## 2.2 模块设计

### 2.2.1 `core/detector.py`

**职责**：调用 YOLOv8 完成目标检测，再用简化 IoU 跟踪器维护 track_id。

**关键类**：

| 类 | 关键方法 | 说明 |
| --- | --- | --- |
| `Detection` | dataclass | 单帧单目标检测结果 |
| `SimpleTracker` | `update(detections) -> List[Detection]` | 贪心 IoU 匹配 |
| `PetDetector` | `detect(frame) -> List[Detection]` | YOLO + tracker |

**关键设计**：
- ultralytics 延迟导入，未装时不阻塞其他模块
- 模型缓存到 `data/models/yolov8n.pt`，避免重复下载
- 跟踪器容忍 15 帧丢失

### 2.2.2 `core/behavior.py`

**职责**：对单帧所有 Detection 输出 5 类行为。

**核心算法**：基于历史中心点位移 + ROI 区域 + 时间窗的启发式：

```
if center in food_roi:    -> "eating"
elif center in water_roi:  -> "drinking"
elif mean_motion < rest_px: -> "resting"
elif mean_motion > act_px:  -> "active"
else:                       -> "active"

if state=="resting" for > anomaly_sec and jitter < epsilon:
    -> "anomaly"
```

**关键类**：

| 类 | 关键方法 |
| --- | --- |
| `BehaviorAnalyzer` | `update(detections, frame_size, ts)` |
| `BehaviorOutput` | dataclass, 单帧单目标行为 |

**状态切换**：当行为变化时，自动把上一段时长写入 `behavior_summary` 表。

### 2.2.3 `core/database.py`

**职责**：SQLite 访问。

**表结构**：

```sql
pet_events       (id, ts, track_id, species, behavior, confidence,
                  bbox_x1, bbox_y1, bbox_x2, bbox_y2, source)
behavior_summary (id, track_id, behavior, start_ts, end_ts, duration_sec)
alerts           (id, ts, level, track_id, behavior, message, acknowledged)
snapshots        (id, ts, track_id, behavior, path)
daily_stats      (day, total_events, rest_sec, active_sec, eat_sec,
                  drink_sec, anomaly_sec, alert_count)
app_meta         (key, value)
```

**特性**：
- WAL 模式 + `synchronous=NORMAL`，提高并发
- 单例 `get_db()`，所有模块共享
- 自动建表（`CREATE TABLE IF NOT EXISTS`，可平滑升级既有库）
- 内置统计 API：`stats_overview()` / `hourly_activity(date)` / `daily_summary(date)` / `upsert_daily_stats(date)` / `export_events_csv(path)`

### 2.2.4 `core/alert.py`

**职责**：集中报警 + 冷却 + 蜂鸣 + 落库。

**API**：

```python
get_alert().raise_(
    level="warning" | "info" | "critical",
    message=...,
    track_id=..., behavior=...,
    cooldown_key=...,        # 同类报警冷却
)
```

**回调**：UI 可注册 `set_popup_callback`，报警时回调。

### 2.2.5 `core/monitor.py`

**职责**：把所有模块串起来。

```
VideoCapture → PetDetector → BehaviorAnalyzer
                                ↓
                          AlertSystem.raise_
                                ↓
                          Database.insert_event
                                ↓
                          Frame.draw(bbox+label)
                                ↓
                          callback(frame_result)
```

**线程模型**：
- `Monitor._run()` 在后台线程读取帧
- 通过 `on_result` 回调把 `FrameResult` 推给 UI 的 `_StateBridge`
- `_StateBridge` 通过 `pyqtSignal` 把结果 emit 到主线程
- 主线程 `MainWindow._on_frame()` 更新 UI

### 2.2.6 `core/snapshot.py`

**职责**：报警快照落盘（JPEG）+ 冷却去重。

**关键点**：
- 关键报警（异常）强制截图，进食/饮水按冷却节流
- 文件名含 `行为_trackID_时间戳_毫秒`，同一秒内不冲突
- **跨平台安全**：用 `cv2.imencode` + 标准文件写入，规避 `cv2.imwrite` 在 Windows 含中文路径下静默失败的问题

### 2.2.7 `core/report.py`

**职责**：从数据库聚合，产出自包含 HTML 报告与 CSV 导出。

- 报告含：总览卡片、行为时长分布（横向条形图）、24 小时分时活动（堆叠柱状图）、最近报警表、快照画廊
- 图表为内联 SVG，零外部依赖，双击 HTML 即可在浏览器查看
- 快照图片以 `file://` URL 引用，中文路径正常显示

### 2.2.8 `scripts/train_model.py`

**职责**：在 yolov8n 预训练权重上微调自定义宠物数据集。

- 自动生成 `data.yaml`，支持本地 YOLO 格式或 Roboflow 目录
- 训练完成后把 `best.pt` 复制到 `data/models/`，监测时设 `PET_MODEL=best.pt` 即可加载

## 2.5 关键算法说明

### 2.5.1 简化 IoU 跟踪器

不做 ReID / Kalman 滤波，直接用帧间 bbox IoU 贪心匹配：

```python
def update(self, detections):
    # 1. 计算 IoU 矩阵 (n_dets x n_tracks)
    # 2. 按 IoU 从大到小排序
    # 3. 贪心匹配，阈值 > 0.3 算匹配
    # 4. 未匹配的检测 → 分配新 track_id
    # 5. 未匹配的轨迹 → missing += 1，超过 max_missing 删除
```

优点：实现简单、零依赖；缺点：宠物长时间重叠会混淆 ID。本项目假设宠物之间不重叠，符合家庭场景。

### 2.5.2 行为分类

不训练自定义分类模型，使用**几何 + 运动 + 位置**启发式，避免了收集大量带标注的行为数据集。

| 行为 | 关键证据 |
| --- | --- |
| eating | center ∈ food_roi |
| drinking | center ∈ water_roi |
| resting | mean_motion_30frames < resting_motion_px (6.0) |
| active | mean_motion > active_motion_px_per_frame (8.0) |
| anomaly | resting 持续 > 60s 且 jitter < 1.5px |

## 2.6 配置管理

所有阈值集中在 `config.py` 的 dataclass 中，可通过环境变量覆盖：

```
PET_MODEL=yolov8n.pt
PET_CONF=0.35
PET_IOU=0.45
PET_DEVICE=cuda:0
```

GUI 中的滑杆同步更新 `CONFIG` 对象，立即生效。

### 2.6.1 配置持久化

- `save_config()` 把当前可调参数写入 `data/config.json`
- `load_config()` 启动时恢复上次的参数
- GUI 启动自动加载、关闭自动保存；`--report` 等 CLI 场景不受影响

## 2.7 异常处理

| 模块 | 处理 |
| --- | --- |
| VideoCapture 打开失败 | `AlertSystem.raise_(CRITICAL, ...)` |
| YOLO 模型加载失败 | 抛出异常，GUI 弹窗 |
| 数据库写入失败 | log.warning，不打断主循环 |
| 报警蜂鸣失败 | 降级到终端响铃 |

## 2.8 部署

- **开发**：直接 `python main.py`
- **打包**：`pyinstaller pet_monitor.spec` → `dist/PetBehaviorMonitor/PetBehaviorMonitor.exe`
- **打包后**：模型仍需下载；可提前把 `yolov8n.pt` 放入 `data/models/`

## 2.9 拓展方向

1. 多宠物同时监控（已支持，仅 UI 表格需要分页）
2. 自定义行为分类（`train_model.py` 微调检测模型，或训练行为分类器替换启发式）
3. Web 推送（Flask + SSE，远程查看）
4. 移动端 App（Flutter 远程报警）
5. 数据可视化增强（已内置 SVG 报告 + QPainter 图表，可扩展时序趋势）

## 2.10 设计原则

| 原则 | 体现 |
| --- | --- |
| 单一职责 | 每个 core 模块只做一件事 |
| 开闭 | 算法可替换（detector / analyzer 接口稳定） |
| 依赖倒置 | UI 依赖抽象的 callback，不直接调后端 |
| 配置外置 | 阈值在 `config.py`，不硬编码 |
| 可观测 | 全链路日志 + 数据库 |
