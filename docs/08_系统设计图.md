# 08 · 系统设计图

> 本文档用 Mermaid 描述系统架构、数据流、数据库 ER、行为判定流程与监控线程时序。
> GitHub / VS Code Mermaid 预览可直接渲染为图片，答辩 PPT 截图即可使用。

---

## 一、系统分层架构图

系统采用经典的四层结构：**UI 层 → 核心层 → 数据层 → 模型层**。UI 层只负责展示与交互，核心层把检测、跟踪、行为识别、报警、快照、统计串成数据通路，数据层用 SQLite 持久化，模型层封装 YOLOv8。

```mermaid
flowchart TB
    subgraph UI["UI 层 (PyQt5)"]
        MW["main_window.py<br/>主窗口·5标签页"]
        VW["video_widget.py<br/>视频显示"]
        CH["charts.py<br/>纯QPainter柱状图"]
    end

    subgraph CORE["核心层 (pet_monitor.core)"]
        MON["monitor.py<br/>监控引擎·粘合层"]
        DET["detector.py<br/>YOLO检测+跟踪"]
        BEH["behavior.py<br/>行为识别(5类)"]
        ALR["alert.py<br/>分级报警+冷却"]
        SNP["snapshot.py<br/>报警快照存证"]
        RPT["report.py<br/>HTML报告+CSV"]
    end

    subgraph DATA["数据层 (SQLite)"]
        DB[("database.py<br/>6张表·WAL模式")]
    end

    subgraph MODEL["模型层"]
        YOLO[("YOLOv8s.pt<br/>COCO预训练·猫15狗16")]
        FLOW["光流(Farneback)<br/>辅助行为判定"]
    end

    MW -->|启动/停止| MON
    MON -->|帧| VW
    MON -->|回调FrameResult| MW
    MON --> DET
    MON --> BEH
    MON --> ALR
    ALR --> SNP
    MON --> DB
    ALR --> DB
    BEH --> DB
    SNP --> DB
    DET --> YOLO
    BEH -.->|光流幅值| FLOW
    MW --> RPT
    RPT --> DB
    MW --> CH
    CH --> DB
```

**设计要点**

- **单向依赖**：UI 层只调用核心层公开 API，核心层不反向引用 UI（线程安全，`_StateBridge` 用信号跨线程传递 `FrameResult`）。
- **粘合层模式**：`monitor.py` 是唯一的"编排者"，detector/behavior/alert/snapshot/database 互相不直接耦合，便于单元测试时整体替换（见 `TestMonitorAlerting`）。
- **零外部服务依赖**：YOLO 离线推理、SQLite 本地存储、报告自包含 HTML（内联 CSS+SVG），换台电脑克隆仓库即可运行。

## 二、单帧数据流图

描述一帧画面从摄像头/视频读入，到最终落库、报警、快照、绘制回显的完整通路。

```mermaid
flowchart LR
    CAM["摄像头/视频文件"] -->|cv2.read 帧| MON["Monitor._run 主循环"]
    MON -->|frame| DET["PetDetector.detect"]
    DET -->|YOLO推理| YOLO[("YOLOv8s")]
    DET -->|Detection列表| TRK["SimpleTracker.update<br/>IoU贪心匹配"]
    TRK -->|带track_id的Detection| BEH["BehaviorAnalyzer.update"]
    BEH -->|BehaviorOutput列表| DRAW["Monitor._draw<br/>画框+中文标签"]
    BEH -->|状态变化| ALERT["Monitor._maybe_alert"]
    ALERT -->|critical| SNP["SnapshotManager.save<br/>报警快照存证"]
    ALERT --> DB2[("alerts表")]
    MON -->|每帧事件| DB1[("pet_events表")]
    BEH -->|状态切换| DB3[("behavior_summary表")]
    SNP --> DB4[("snapshots表")]
    DRAW -->|FrameResult| UI["UI 主线程绘制"]
    ALERT -->|弹窗| POP["桌面通知"]
```

**关键流转**

| 环节 | 频率 | 落库表 |
| --- | --- | --- |
| 每帧检测事件 | ~25 FPS | `pet_events` |
| 行为状态切换 | 状态变化时 | `behavior_summary` |
| 分级报警 | 状态变化+冷却 | `alerts` |
| 报警快照 | critical 强制 / info 可选 | `snapshots` |
| 每日汇总 | 手动/定时 | `daily_stats` |

## 三、数据库 ER 图

共 6 张表。`pet_events` 是高频写入的事件流，`behavior_summary` 是状态段汇总，`alerts`/`snapshots` 由报警触发，`daily_stats` 是按天聚合，`app_meta` 存应用元数据。

```mermaid
erDiagram
    pet_events ||--o{ behavior_summary : "track_id 关联"
    pet_events {
        INTEGER id PK
        REAL ts
        INTEGER track_id
        TEXT species
        TEXT behavior
        REAL confidence
        REAL bbox_x1
        REAL bbox_y1
        REAL bbox_x2
        REAL bbox_y2
        TEXT source
    }
    behavior_summary {
        INTEGER id PK
        INTEGER track_id
        TEXT behavior
        REAL start_ts
        REAL end_ts
        REAL duration_sec
    }
    alerts {
        INTEGER id PK
        REAL ts
        TEXT level
        INTEGER track_id
        TEXT behavior
        TEXT message
        INTEGER acknowledged
    }
    snapshots {
        INTEGER id PK
        REAL ts
        INTEGER track_id
        TEXT behavior
        TEXT path
    }
    daily_stats {
        TEXT day PK
        INTEGER total_events
        REAL rest_sec
        REAL active_sec
        REAL eat_sec
        REAL drink_sec
        REAL anomaly_sec
        INTEGER alert_count
    }
    app_meta {
        TEXT key PK
        TEXT value
    }
```

**索引**：`pet_events(ts)`、`pet_events(track_id)`、`behavior_summary(track_id)`、`alerts(ts)`、`snapshots(ts)`，保证按时间/目标的查询效率。
**并发**：开启 `journal_mode=WAL` + `synchronous=NORMAL`，监控线程高频写、UI 线程并发读不阻塞。

## 四、行为判定决策流程图

`BehaviorAnalyzer._classify` 对单个 track 的判定顺序：先 ROI（食盆/水盆），再运动量静止/活跃，最后长时静止升级异常。优先级从上到下短路。

```mermaid
flowchart TD
    START["收到该track的本帧Detection"] --> H{"历史≥3帧?"}
    H -- 否 --> UNK["unknown"]
    H -- 是 --> ROI{"中心点在<br/>食盆ROI内?"}
    ROI -- 是 --> EAT["eating"]
    ROI -- 否 --> WAT{"中心点在<br/>水盆ROI内?"}
    WAT -- 是 --> DRK["drinking"]
    WAT -- 否 --> MVT["计算motion/jitter"]
    MVT --> R{"motion < 静止阈值?"}
    R -- 是 --> RST["resting"]
    R -- 否 --> ACT["active"]
    RST --> ANO{"静止持续>60s<br/>且jitter<1.5px<br/>且motion极低?"}
    ANO -- 是 --> AML["anomaly<br/>疑似晕厥/抽搐"]
    ANO -- 否 --> RST
    EAT --> EMIT["状态切换→写summary+报警"]
    DRK --> EMIT
    RST --> EMIT
    ACT --> EMIT
    AML --> EMIT2["critical报警+强制快照"]
    UNK --> END["返回"]
    EMIT --> END
    EMIT2 --> END
```

**判定依据（启发式，零监督学习）**

| 行为 | 主判据 | 辅判据 |
| --- | --- | --- |
| eating | 中心点 ∈ food_roi | 停留 ≥ consum_min_dwell_sec |
| drinking | 中心点 ∈ water_roi | 停留 ≥ consum_min_dwell_sec |
| resting | motion < resting_motion_px | 持续 ≥ rest_min_duration_sec |
| active | motion > active_motion_px_per_frame | — |
| anomaly | resting 持续 > 60s + 微抖动 | motion < 静止阈值×0.5 |

> 局限：纯几何/运动启发式对"睡觉 vs 晕厥"区分有限；后续可引入光流（已接入 `behavior._flow_magnitude`）或姿态/时序模型提升。

## 五、监控线程时序图

`Monitor` 起一个后台守护线程读帧，UI 主线程不阻塞。`_StateBridge` 用 Qt 信号把后台结果安全送到主线程。

```mermaid
sequenceDiagram
    participant UI as UI主线程
    participant BR as _StateBridge
    participant T as Monitor线程
    participant DET as PetDetector
    participant BEH as BehaviorAnalyzer
    participant DB as Database
    participant SNP as Snapshot

    UI->>T: start()
    T->>T: cv2.VideoCapture(source)
    loop 每帧
        T->>T: cap.read()
        T->>DET: detect(frame)
        DET->>DET: YOLO推理+IoU跟踪
        DET-->>T: Detection[]
        T->>BEH: update(detections, frame_size)
        BEH-->>T: BehaviorOutput[]
        T->>DB: insert_event(每帧)
        T->>BEH: 状态变化?
        alt 状态变化
            T->>DB: insert_behavior_summary
            T->>SNP: save(报警快照)
            T->>DB: insert_alert / insert_snapshot
        end
        T->>T: _draw(画框+标签)
        T->>BR: submit(FrameResult)
        BR-->>UI: frame_ready信号
        UI->>UI: show_frame(主线程绘制)
    end
    UI->>T: stop()
    T->>T: cap.release()
```

**线程安全要点**

- 后台线程**只**通过 `on_result` 回调（经 `_StateBridge` 信号）与 UI 通信，绝不直接操作控件。
- `Database` 内部用 `threading.Lock` 串行化所有连接，WAL 模式下读不阻塞写。
- `AlertSystem` 的蜂鸣/弹窗通过回调在主线程触发（PyQt5 控件不可在非主线程创建）。
