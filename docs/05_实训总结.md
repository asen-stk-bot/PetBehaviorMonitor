## 5.2 选题说明

任务书给出了 10 个选题（皮带偏移、安全帽、烟火、异物、施工车辆、人脸、皮带撕裂、手势、异构视频源、边缘设备资源监控），均为工业监控场景。考虑到：

1. 工业场景的数据采集与展示受限，家庭宠物场景便于课程演示与答辩；
2. YOLOv8 在 COCO 上预训练了猫（15）与狗（16），可以直接作为本系统的检测器；
3. 宠物行为识别在工程上具有通用性（异常静止 = 健康预警），具备实用价值。

经指导教师张冰老师同意，最终选定 **"宠物行为识别监测系统"** 作为本次实训课题。

## 5.5 系统功能总结

本系统实现了以下功能（全部通过单元/集成测试）：

1. ✅ 实时视频源接入（USB 摄像头 / 视频文件 / 演示视频）
2. ✅ 基于 YOLOv8 的猫狗检测（置信度与 IoU 可调）
3. ✅ 基于简化的 IoU 跟踪器跨帧维持宠物 ID
4. ✅ 5 类行为识别（休息 / 活动 / 进食 / 饮水 / 异常）
5. ✅ SQLite 数据库自动记录事件与行为汇总
6. ✅ 异常行为触发蜂鸣报警 + 冷却机制
7. ✅ 报警快照自动截图存证
8. ✅ 行为统计分析（分时活动 / 每日汇总 / 时长占比）
9. ✅ 一键生成 HTML 报告（含图表）与 CSV 导出
10. ✅ PyQt5 GUI（5 标签页 + ROI 可视化 + 柱状图 + 快照画廊）
11. ✅ 阈值实时调整 + 配置持久化（跨会话恢复）
12. ✅ YOLOv8 微调训练脚本（补齐模型训练环节）
13. ✅ 一键打包为 exe（PyInstaller）
14. ✅ 合成演示视频（无需真实宠物即可演示流程）

## 5.6 遇到的困难与解决

| 困难 | 解决 |
| --- | --- |
| ultralytics 自动下载失败（路径含中文） | 把模型缓存目录改到 ASCII 路径 `data/models/` |
| CPU 推理慢 | 选 yolov8n + imgsz=640 + 减小 ROI 计算开销 |
| 跟踪 ID 在宠物重叠时混淆 | 假设家庭场景宠物不重叠；记录为已知限制（ISS-04） |
| YOLO 不识别合成视频 | 生成脚本改用真实纹理，但训练成本过高；记录为已知限制（ISS-01） |
| PyQt5 跨线程更新 UI 崩溃 | 用 `pyqtSignal` + `_StateBridge` 把后台结果 emit 到主线程 |
| 报警刷屏 | 同类报警 30 秒冷却 |
| `cv2.imwrite` 在中文路径下静默失败 | 改用 `cv2.imencode` + 标准文件写入，快照稳定落盘 |
| 报警时监控线程崩溃（`LEVEL_INFO` 未导入） | 通过注入式假检测器复现并补齐导入 |
| 快照同一秒互相覆盖 | 文件名加入毫秒精度 |

## 5.8 心得体会

通过本次实训，我体会到：

1. **软件工程不是写代码**——需求、文档、测试同样重要；
2. **算法不等于工程**——YOLOv8 一行代码能调，但要做成产品需要工程化设计；
3. **迭代开发**——本项目从最简单的"显示视频"开始，逐步叠加检测、跟踪、行为、报警；
4. **用户视角**——GUI 阈值可调、报警冷却，都是从"宠物主不会一直盯着屏幕"这个场景出发的；
5. **跨学科**——机器视觉、数据库、GUI、打包，每一项都不深，但综合在一起就是一套完整项目。
