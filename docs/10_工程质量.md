## 二、类型检查（mypy）

| 项 | 配置 |
|----|------|
| 工具 | mypy |
| 配置文件 | `mypy.ini`（项目根） |
| 现状 | **0 错误 / 15 源文件** |

### 2.1 严格度策略

```ini
[mypy-pet_monitor.ui.*]
ignore_errors = True
[mypy-pet_monitor.core.alert]
ignore_errors = True
[mypy-pet_monitor.core.detector]
ignore_errors = True
[mypy-pet_monitor.core.behavior]
ignore_errors = True
```

**理由**：
- **UI 层**：PyQt5 官方 type stubs 覆盖不全（statusBar、QSystemTrayIcon 枚举等都有缺失），强行严格会大量误报。
- **alert/detector/behavior**：强依赖 ultralytics + opencv-python 的运行时类型，stub 与实际行为存在偏差；这些模块已有单测覆盖核心行为，类型严格度价值低于维护成本。
- **其余 core 模块**（config、database、monitor、report、snapshot、video_source）走严格检查，保证数据结构契约。

### 2.2 跑类型检查

```bash
mypy src/pet_monitor
# 或指定源
mypy src/pet_monitor/core
```

## 三、持续集成（GitHub Actions CI）

配置文件：`.github/workflows/ci.yml`

### 3.1 触发条件

- push 到 `main` / `master` 分支
- 对 `main` / `master` 的 pull_request

### 3.2 流水线步骤

1. **检出代码** — `actions/checkout@v4`
2. **设置 Python 3.9** — `actions/setup-python@v5` + pip 缓存
3. **安装依赖** — `requirements.txt` + pytest + pytest-cov + mypy
4. **跑测试 + 覆盖率** — `pytest tests/ --cov=src/pet_monitor --cov-report=xml`
5. **跑类型检查** — `mypy src/pet_monitor`
6. **上传覆盖率**（可选） — `codecov/codecov-action@v4`
