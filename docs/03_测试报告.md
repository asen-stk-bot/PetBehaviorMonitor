# 03 · 测试报告

## 3.1 测试策略

| 测试类型 | 工具 | 范围 |
| --- | --- | --- |
| 单元测试 | `unittest` | 数据库 / 跟踪器 / 行为分析器 / 报警 / 统计 / 快照 / 报告 / 配置 |
| 集成测试 | 手动 | 启动 → 检测 → 行为 → 数据库 → 报警 → 快照 → UI |
| 系统测试 | 手动 | 演示视频 + 摄像头 |
| 性能测试 | 手动 | FPS 测量 |

测试原则：
- 单元测试覆盖**纯算法逻辑**（不依赖 ultralytics/cv2/PyQt5 安装）
- 集成测试在用户机器上以演示视频自动运行
- 监控报警接线用**注入式假检测器**做回归测试，避免依赖 YOLO 推理

## 3.4 集成测试结果

**场景 A：演示视频**

```
$ python main.py --demo
[INFO] pet_monitor.monitor: 监控启动: source=data/videos/demo.mp4
[INFO] pet_monitor.monitor: 监控停止: source=data/videos/demo.mp4, frames=1250

UI 行为：
  1. 视频区显示合成猫/狗矩形
  2. 猫在不同阶段被识别为 active / eating / drinking / resting
  3. 报警页产生 "cat#1 正在进食" 信息级报警
  4. 事件表持续追加记录
  5. 统计页显示行为时长分布
```

**场景 B：USB 摄像头（i5-8250U / 无 GPU）**

```
yolov8n.pt 自动下载，缓存到 data/models/
第一次推理预热 ~2s（1928ms 冷启动）
稳态 FPS ≈ 38（实测 302 帧 / 8 秒 = 37.7 FPS）
```

**端到端实测**（演示视频，2026-09-01 实测）：

```
监控引擎：302 帧 / 8 秒 = 37.7 FPS（CPU i5-8250U）
合成视频上无 cat/dog 检测（合成矩形被 YOLO 视为背景，符合 ISS-01）
数据库：0 events（合成视频不触发行为）
```

## 3.7 已知问题与限制

| 编号 | 描述 | 应对 |
| --- | --- | --- |
| ISS-01 | 演示视频是合成矩形，YOLO **不会**识别为猫/狗（缺少猫狗纹理特征） | 启动后右上角"控制"页可看到 detections=0；用真实宠物视频测试 |
| ISS-02 | 长时间静止后误报"异常" | 可调整 `anomaly_min_duration_sec` 到 120+ |
| ISS-03 | YOLO 把猫误识别为狗 | 提高 `conf_threshold` 到 0.5 |
| ISS-04 | 多只宠物严重重叠时 ID 会切换 | 当前假设宠物不重叠 |
| ISS-05 | 高分辨率视频（4K）CPU FPS 严重下降 | 在 GUI 调小 `imgsz` 或换 yolov8n |

## 3.9 测试结论

- ✅ 全部 21 个单元测试通过（10 基础 + 11 新增）
- ✅ 集成测试：演示视频 + UI 全链路可演示

## 3.10 测试中发现并修复的缺陷

| 编号 | 缺陷 | 严重度 | 修复 |
| --- | --- | --- | --- |
| BUG-01 | `monitor.py` 使用 `LEVEL_INFO` 但未导入，宠物进食/饮水时监控线程崩溃 | P1 严重 | 补充 `LEVEL_INFO` 导入 |
| BUG-02 | `cv2.imwrite` 在 Windows 中文路径（`程祥凯`）下静默失败，快照无法落盘 | P1 严重 | 改用 `cv2.imencode` + 标准文件写入 |
| BUG-03 | 快照文件名仅精确到秒，同一秒多次快照互相覆盖 | P2 一般 | 文件名加入毫秒 |
